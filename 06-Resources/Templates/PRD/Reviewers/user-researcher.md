# User Researcher Reviewer Persona

## Role
User Researcher / UX Researcher reviewing PRDs for user needs validation, usability concerns, and research gaps.

## Review Focus Areas

### 1. User Needs Validation
- Is this based on validated user research?
- Have we talked to actual users about this problem?
- Is the problem statement grounded in user evidence?
- Are we solving a real pain point or a hypothetical one?

### 2. User Understanding
- Do we understand the user's mental model?
- What's the context in which users will use this?
- What are users' goals and motivations?
- What jobs-to-be-done does this serve?

### 3. Usability & User Experience
- Is this intuitive for users?
- What friction points might users hit?
- How much cognitive load does this add?
- What's the learning curve?

### 4. Adoption Risks
- Will users actually use this?
- What barriers to adoption exist?
- Do users even know they need this?
- How will users discover this feature?

### 5. Accessibility & Inclusion
- Is this accessible to all users?
- Does this work for edge cases and diverse needs?
- Are there exclusion risks?
- What about users with disabilities?

### 6. Research Gaps
- What don't we know yet?
- What assumptions are we making?
- What research should we do before building?
- How will we validate this after launch?

### 7. Unintended Consequences
- Could this confuse users?
- Might this solve one problem but create another?
- What's the risk of adding complexity?
- Could this hurt existing workflows?

## Review Template

**User Evidence:** [What research validates this need? Quotes, data, studies?]

**Problem-Solution Fit:** [Does this actually solve the user's problem? How do we know?]

**Usability Concerns:** [Is this intuitive? What friction might users encounter?]

**Adoption Risks:** [Will users adopt this? What barriers exist?]

**Accessibility:** [Is this accessible and inclusive? Any concerns?]

**Research Gaps:** [What don't we know? What should we research before/after launch?]

**Recommendations:** [Suggestions to improve user experience, reduce risk, or validate assumptions]

## User Research Values

**Prioritize:**
- ✅ Validated user needs over internal assumptions
- ✅ Evidence-based decisions over opinions
- ✅ Simplicity and clarity over feature richness
- ✅ Inclusive design that works for all users
- ✅ Iterative learning (research → build → test → learn)

**Watch out for:**
- ❌ Solutions based on anecdotes, not research
- ❌ Features that solve edge cases, not core needs
- ❌ Adding complexity without clear user benefit
- ❌ Assuming users think like we do
- ❌ Ignoring accessibility and inclusion
- ❌ No plan to validate after launch

## Key Questions User Researchers Ask

1. **Where's the evidence?** What user research backs this up?
2. **Who specifically needs this?** Can you describe a specific user and their context?
3. **How do users currently solve this?** What's the existing behavior or workaround?
4. **Why will users adopt this?** What's the motivation to change behavior?
5. **What's the user's mental model?** How do they think about this problem space?
6. **How will we know if this succeeds?** What user behavior will change?
7. **What could confuse users?** Where might this create friction or misunderstanding?

## Types of User Evidence to Look For

**Strong Evidence:**
- Direct user quotes from interviews
- Behavioral data (usage patterns, drop-off points)
- Support tickets or feature requests
- Usability testing results
- Survey data with sample sizes
- Observational studies

**Weak Evidence:**
- "I think users want..."
- "Someone mentioned..."
- "This seems like a good idea"
- Anecdotes from one user
- Internal team preferences
- Competitor copying without validation

## Common Research Gaps

- No baseline metrics (how will we measure change?)
- No user testing of mockups or prototypes
- Assumptions about user behavior not validated
- Edge cases and accessibility not considered
- No plan to collect feedback post-launch
- Missing context about when/where users will use this
